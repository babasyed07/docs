title: "Application Context Overview"
subtitle: "**Reva enables application context configuration for unified policy governance.**"
---

With Reva, you don’t onboard applications themselves. Instead, you configure the application context to simplify the management of policy stores across environments. This ensures policies remain consistent while giving you the flexibility to organize applications, map them to the right policy stores, and align with governance requirements.  
1. **Properly identified and categorized** – Ensures each application is distinctively managed within the organization.  
2. **Linked to its operational environments** – Ensures seamless integration and correct resource allocation across all stages.  
3. **Governed by security policies** – Guarantees compliance with internal and regulatory security requirements before activation.  

## What You Can Do  
1. **+ New Application Context:** Define metadata such as name, category, tags, and owners to represent the application.  
2. **Policy Store Mapping:** Associate each application context with a policy store, ensuring policies are managed per environment.  
3. **Environment Linking:** Reva automatically links a default environment, with the option to add more (e.g., dev, staging, prod).  
4. **Attributes and Tags:** Add identifiers like tags and owners for accountability and searchability.  
5. **Settings and Actions:** Use the three vertical dots (⋮) to edit or delete the application context.  

## Why This Matters  
- **Unified Governance:** Manage policy stores across environments through a single application context.  
- **Simplified Management:** Group environments under logical application contexts for easier oversight.  
- **Consistency:** Ensure environments remain aligned with the same governance model.  
- **Visibility and Compliance:** Track ownership, categories, and actions for accountability.
