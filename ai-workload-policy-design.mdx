Once your [agents are modeled](/ai-workload-context-modeling), you write policies that decide which calls in an agent chain are allowed. Reva's Policy Designer gives you a visual builder and a Cedar code editor, both backed by versioned policy stores with approval workflows.

## The Agentic Policy Model

Every agentic policy answers the same four questions, plus runtime context:

| Component | In an agent chain | Example |
|:----------|:------------------|:--------|
| **Principal** | Who is making the call | `Agent::"shipment-supervisor-agent"`, `User::"john"` |
| **Action** | What kind of call | `invokeAgent`, `invokeTool`, `invokeModel` |
| **Resource** | What is being called | `Agent::"billing-agent"`, `MCP::"reva-rate-mcp"` |
| **Context** | Runtime facts to test | `context.onBehalfOf`, `context.environment`, `context.intent` |

## Two Ways to Author

1. **Visual Mode (business-friendly)** — define principals, actions, resources, and conditions on a graph-based canvas. The Condition Builder constructs logic with attribute selectors and operators, no code required.
2. **Developer Mode (Cedar)** — write Cedar directly for maximum control, with full syntax support.

<Info>
  **Schema first.** Before authoring policies, make sure your agentic entities and attributes exist in the schema (see [Context Modeling](/ai-workload-context-modeling) and [Add Runtime Attributes](/ai-workload-schema-runtime-attributes)). Policies can only reference entities and attributes the schema defines.
</Info>

## Policy Styles

Agentic authorization commonly uses three policy styles. You can combine them.

| Style | Decides based on | Typical use |
|:------|:-----------------|:------------|
| **Context-based** | Runtime values passed with the call (`context.*`) | Restrict a tool call to a specific resource or condition |
| **On-Behalf-Of (OBO)** | The delegating user carried in `context.onBehalfOf` | Make an agent act only within the user's risk/scope |
| **Intent-based** | The purpose/intent of the request | Allow only calls whose intent the caller is permitted to make |

<Note>
  The examples below are **starting points** — adapt the entity ids, attributes, and conditions to your own schema, then validate them in [Policy Testing](/ai-workload-policy-testing) before publishing.
</Note>

### Context-Based Policies

Decide using values supplied at runtime in `context`. Here, the rate tool may be invoked **only** for a specific container id:

<CodeGroup>
```cedar Context-based (example placeholder)
permit (
    principal,
    action   == Action::"invokeTool",
    resource == MCP::"reva-rate-mcp"
)
when { context.container_id == "MSCU4429881" };
```
</CodeGroup>

### On-Behalf-Of (OBO) Policies

Decide using the delegating user carried in `context.onBehalfOf`. Here, an agent may act **only** when it is operating on behalf of a low-risk user:

<CodeGroup>
```cedar On-behalf-of (example placeholder)
permit (
    principal,
    action == Action::"invokeAgent",
    resource
)
when { context.onBehalfOf.riskTier == "LOW" };
```
</CodeGroup>

### Intent-Based Policies

Decide using the purpose of the request. Here, a tool call is allowed **only** when its intent is one the caller is permitted to make:

<CodeGroup>
```cedar Intent-based (example placeholder)
permit (
    principal,
    action == Action::"invokeTool",
    resource
)
when { context.intent in principal.allowedIntents };
```
</CodeGroup>

## Generate Policies with Reva AI

You don't have to start from a blank canvas. Reva AI can draft agentic policies from a plain-English description, which you then review and refine.

<Card title="AI-Generated Access Policy" icon="wand-magic-sparkles" href="/ai-workload-policy-generated">

## Publish Policies

1. Review your draft policies in the **Summary of Policies** view and use **Impact** to preview the access relationships.
2. Click **Publish** to activate. If approval is required (for non-owner contributors), the draft moves to **Pending Actions** for review.

<Info>
  Before publishing, configure **Policy Publish settings** in the policy store (policy type and connection details). Without this configuration, publishing is not possible.
</Info>
