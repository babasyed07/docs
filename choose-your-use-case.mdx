Reva applies the same Cedar policy engine to several authorization use cases. Each one has its own guided path in this documentation, but they share the same concepts, policy language, and governance tools — so what you learn in one carries over to the next.

Pick the use case that matches your goal.

## Pick Your Use Case

<CardGroup cols={2}>
  <Card title="Custom Application Authorization" icon="layer-group" href="/manage-policies">
    Add fine-grained access control to your own applications and APIs. Model RBAC, ABAC, and ReBAC with Cedar, test with the Access Map, and enforce via the Reva SDK or Amazon Verified Permissions.
  </Card>
  <Card title="AI Workload Security" icon="robot" href="/ai-workload-security-overview">
    Authorize every call in your agentic AI systems — user → agent, agent → agent, agent → tool, MCP server, and model — at runtime through the Reva Trust Guardian.
  </Card>
  <Card title="Token Enrichment" icon="key" href="/enrich-identity-tokens-with-policy-based-claims">
    Add policy-based claims, roles, applications, and entitlements to identity tokens during sign-in, so downstream apps can decide access without a separate call.
  </Card>
  <Card title="Infrastructure / OPA (coming soon)" icon="circle-plus">
    OPA-based infrastructure authorization and additional use cases are on the roadmap. Reva's vertical model is built to extend.
  </Card>
</CardGroup>

## Compare Use Cases

| Use case | What it secures | Where it's enforced | Start here |
|:---------|:----------------|:--------------------|:-----------|
| **Custom Application Authorization** | Your applications and APIs | In your app (Reva SDK / AVP PEP) | [Manage Policies](/manage-policies) |
| **AI Workload Security** | Agent chains — agents, tools, MCP servers, models | At runtime, via the Reva Trust Guardian + `reva-ai-authz` SDK | [AI Workload Security Overview](/ai-workload-security-overview) |
| **Token Enrichment** | Identity tokens at sign-in | At the Identity Provider, via the Reva Trust Guardian | [Enrich Identity Tokens](/enrich-identity-tokens-with-policy-based-claims) |
