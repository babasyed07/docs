title: "AI Workload Decision Logs"
description: "Audit every authorized call in an agent chain and trace it end to end."
---

Every PDP decision — allow or deny — is recorded in the decision logs. For agentic workloads this gives you a per-hop audit trail across an entire agent chain, correlated by a shared `threadId`.

## What Each Decision Log Shows

| Field | Meaning |
|:------|:--------|
| **timestamp** | When the decision was made |
| **principal** (+ type) | Who made the call — `User` or `Agent` |
| **action** | `invokeAgent`, `invokeTool`, `invokeModel`, … |
| **resource** (+ type) | What was called — `Agent`, `MCP`, `Model`, `API` |
| **decision** | `Allow` or `Deny` |
| **onBehalfOf** | The delegating user the agent acted for |
| **threadId** | Correlation id tying every hop of one chain together |
| **requestId** | Unique id for the individual evaluation |

## View Decision Logs

1. Open the policy store for your AI workload.
2. Go to the **Decision Logs** tab.
3. Filter by principal, action, resource, decision, or time range to find the calls you care about.
4. Open a row to see the full evaluation context and the policy that determined the result.

## Trace an Agent Chain End to End

Because every hop shares the same `threadId`, you can reconstruct an entire request. For example, one chat turn:

| timestamp | principal | type | action | resource | type | decision |
|:----------|:----------|:-----|:-------|:---------|:-----|:---------|
| 12:11:02 | john | User | invokeAgent | shipment-supervisor-agent | Agent | Allow |
| 12:11:02 | shipment-supervisor-agent | Agent | invokeTool | reva-carrier-mcp | MCP | Allow |
| 12:11:05 | shipment-supervisor-agent | Agent | invokeAgent | compliance-agent | Agent | Allow |
| 12:11:08 | compliance-agent | Agent | invokeTool | reva-compliance-mcp | MCP | Deny |

The final **Deny** shows exactly where and why the chain was stopped — end-to-end traceability across request → policy → token hops.
