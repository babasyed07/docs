---
title: "Create Design Time Guardrail Rules"
description: "Use predefined rules or create custom rules to evaluate policies during design time."
---

Design Time Guardrail Rules define what Reva checks when a policy is created or edited in Policy Designer. A guardrail can include one or more rules.

Reva supports two ways to configure design time guardrail rules:

1. Use predefined rules from the **Guardrail Rules** tab.
2. Create custom rules from the **Guardrail Rules** tab in Reva.

## Predefined Design Time Rules

When creating a design time guardrail, open the **Guardrail Rules** tab and select the rules that should apply.

Common predefined rules include:  
| Rule | Description |
|---|---|
| **Redundant policies with shared Principal-Resource** | Prevents duplicate policies for the same principal-resource pair. |
| **Prevent Duplicate Policy with same PARC** | Ensures that no two policies use the same Principal-Action-Resource-Condition combination. |
| **Prevent Overly Permissive Policies** | Blocks creation of policies with broad actions such as `All`. |
| **Enforce Mandatory Policy Conditions** | Blocks policy creation or modification unless the policy includes at least one condition. |
| **Prevent Conflicting Policy Effects** | Blocks policies that create permit and deny conflicts for the same principal-action-resource combination. |
| **Use specific resources instead of wildcard** `*` | Detects wildcard resource usage without strict conditions. |

## Create a Custom Rule

Create custom design time guardrail rules from the **Guardrail Rules** tab in Reva. The underlying guardrail service endpoints are internal and are not supported customer APIs.

## Rule Fields
| Field | Required | Description |
|---|---|---|
| **name** | Yes | Name of the custom guardrail rule. |
| **description** | Yes | Explains what the rule detects and why it matters. |
| **regoPolicy** | Yes | Rego policy logic used to evaluate the policy input. |
| **configJson** | No | Optional configuration object for the rule. Use `{}` when no configuration is required. |
| **type** | Yes | Use **DESIGN_TIME** for design time guardrail rules. |

## Example Rule: Missing Policy Condition Detection

This rule detects permit policies that do not include conditions.

```rego
some i
policy := input.entries[i]
policy.type == "permit"
not policy.conditions
```

Use this rule when your organization requires every permit policy to include a condition, such as role, time, location, risk level, or resource scope.

## After Creating a Rule

After the rule is created, it becomes available for selection in the **Guardrail Rules** tab when creating or editing a design time guardrail.
