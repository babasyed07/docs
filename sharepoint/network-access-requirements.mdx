---
title: "Network Access Requirements"
---

In the internal deployment the connector runs in Reva, so the customer network needs no firewall change. The connector makes outbound HTTPS (TCP 443) calls from Reva to the Microsoft endpoints below.

## Microsoft destinations

| Destination | Hostname | Purpose |
| --- | --- | --- |
| Microsoft Entra ID token endpoint | `login.microsoftonline.com` (HTTPS, TCP 443) | `POST /{tenant-id}/oauth2/v2.0/token` with the client credentials. Returns a Graph access token, cached and renewed before it expires. |
| Microsoft Graph | `graph.microsoft.com` (HTTPS, TCP 443) | Every read in section [9](/sharepoint/permissions-the-connector-uses), under `/v1.0`. Per-file details are grouped 20 to a `$batch` request. |

## Reva console

The people who create the integration open the Reva console in a browser to create it, run Test and Sync, read the import status and view the data in Access Explorer.

## Customer tenant settings that can block the connector

- **IP or location restrictions.** If the tenant limits app sign-ins or SharePoint access by IP address (Conditional Access for workload identities, or SharePoint's network location setting), add Reva's outbound IP addresses. Reva provides them for the tenant.
- **Admin consent.** Application permissions only work after an administrator grants consent (section [4.3](/sharepoint/register-the-app-in-microsoft-entra-id#add-the-microsoft-graph-permissions-and-grant-consent)). Without it the token is issued but every Graph read returns 403.
- **Throttling.** Microsoft throttles each app per tenant. The connector waits for the time Graph asks for in `Retry-After`, up to 15 minutes in total per walk, then ends the run and resumes later from its checkpoint. Large first imports run best outside business hours, when Microsoft throttles less.
