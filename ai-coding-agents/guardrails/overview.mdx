For the workspace administrator and the security team reviewing an AI coding agent rollout.

<Note>
  **In one line**

  Guardrails are the checks that run on every action your coding agents attempt — they catch the request that should never have been made, before it runs.
</Note>

An AI coding agent does not hesitate. Asked to clean up a directory, it runs the command. Asked to debug a failing record, it reads whatever you paste. Told by a file it is reading to do something else, it may simply do it. The speed that makes agents useful is the same property that makes a single bad instruction expensive.

Guardrails sit between the agent and the action. Each one watches for a specific class of problem  a credential in a prompt, a destructive shell command, an unsanctioned connector/MCP server, an agent quietly working on something nobody approved  and stops or flags it at the point of execution.

This guide covers every guardrail available to your workspace. Each entry gives the scenario it exists for, an example that triggers it, what the developer sees, and what you are exposed to if you leave it off.

## Where to start

Turning on twelve guardrails at once is the fastest way to have them all turned off again a week later. A staged rollout gets you to the same place with your developers still on side.

- **Week one.** Put every guardrail in Monitor. Nothing is blocked, and you find out what your developers are actually doing — which is rarely what anyone predicts.
- **Week two.** Enforce the guardrails that carry no tuning burden and no legitimate use case: secrets, personal data, destructive commands, prompt injection, content safety, and unsanctioned connectors. These rarely produce a false positive worth arguing about.
- **Week three.** Tune and then enforce the environment-specific ones. File sensitivity needs your category definitions. Device posture needs approved machine lists populated first. Session and sub-agent limits need a week of real numbers before you know what normal looks like.
- **Ongoing.** Review what fired. A guardrail firing constantly against legitimate work is misconfigured, not vindicated — fix the rule rather than asking your developers to live with it.

<Warning>
  Device Posture is the one to sequence carefully. Enforcing it before your approved machine lists are populated will block your entire team at once, including you.
</Warning>

## Glossary

| Term | Meaning |
|:-----|:--------|
| **Guardrail** | A check that runs against an action a coding agent attempts, and either blocks it or records it. |
| **Enforced** | Mode in which a guardrail blocks the action it catches. |
| **Monitor** | Mode in which a guardrail records what it catches without blocking. Used to assess impact before enforcing. |
| **Hard limit** | The threshold at which an action is blocked outright. |
| **Soft threshold** | The lower threshold at which an action is permitted but flagged for review. |
| **Connector** | An external system an agent can reach through a connector server — mail, issue tracking, storage, and similar. |
| **Sub-agent** | An agent spawned by another agent to carry out part of a task, inheriting the parent session’s context. |
| **Intent drift** | The distance between what a user approved and what the agent is now doing. |
| **Prompt injection** | Instructions planted in content the agent reads, written to be followed by the agent rather than the user. |
| **Decision record** | The log of what was attempted, what was decided, and why. Your audit trail. |

## Best practices

- **Agree what you cannot tolerate:** Work through the "Risk exposure without Guardrail" rows above with whoever owns risk in your organization. That conversation is faster with concrete scenarios than with a feature list.
- **Prepare the inputs:** Populate approved machine lists, define your sensitive file categories, and confirm your approved connectors before enforcing the guardrails that depend on them.
- **Start in Monitor:** A week of Monitor data tells you which guardrails are ready to enforce and which need tuning. Enforce from evidence, not from the default.
- **Know where the detail goes:** The decision record is where the reason lives, since the agent is never told. Make sure the people who will be asked "why was this blocked" know where to look.
