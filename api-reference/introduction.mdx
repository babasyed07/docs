# Reva API Reference Overview  
The Reva API provides programmatic access to customer-facing Reva platform services through the API Gateway. Use these APIs to evaluate authorization decisions, secure AI workload execution, and ingest authorization context.

The API reference is organized by functional area so developers can quickly find the right API for each integration use case.

## API groups  
| API group | Purpose |
|---|---|
| **AI Workload Authorization APIs** | Evaluate agent, tool, model, and AI workload authorization requests. |
| **Authorization APIs** | Evaluate access decisions using AuthZEN-compatible requests. |
| **Data Fabric APIs** | Create, update, replace, and delete authorization context data used by Reva policies. |

## Common use cases  
Use the API reference when you want to:

* Evaluate whether a subject can perform an action on a resource.
* Send AuthZEN-compatible authorization requests to Reva.
* Authorize AI agent and tool execution.
* Ingest entities, attributes, and relationships into Reva Data Fabric.

## Authorization APIs  
Authorization APIs evaluate access requests against Reva policies and authorization context.

The AuthZEN-compliant evaluation API uses a subject, action, resource, and optional context request format.

Use this API when your application, gateway, service, or integration needs a real-time allow or deny decision.

## AI Workload Authorization APIs  
AI Workload Authorization APIs are used to evaluate agentic workload activity. These APIs help authorize AI agents, tools, models, and multi-hop workload calls before execution.

Use these APIs when you need to control:

* Which agent can call a tool.
* Which user authority is carried into an agent workflow.
* Which actions are allowed at each step of an AI workload.
* Whether an AI workflow should continue, be blocked, or require additional review.

## Data Fabric APIs  
Data Fabric APIs are used to ingest authorization context into Reva. This context can include users, groups, applications, roles, entitlements, resources, and relationships.

Use these APIs to:

* Create a single entity.
* Create entities in bulk.
* Update entity attributes or relationships.
* Replace existing entity data.
* Delete one entity or all entities for an entity type.

The ingested data becomes part of the authorization context used during policy evaluation.

## Authentication  
Most Reva APIs require authentication. Include the required token in the request header.

```bash
Authorization: Bearer <token>
```

Some APIs may use an API token or service-specific authentication method depending on the integration. Review the endpoint-level authentication requirements before calling an API.

## Request and response format

Most Reva APIs use JSON request and response bodies.

```bash
Content-Type: application/json
Accept: application/json
```

File upload or download APIs may use `multipart/form-data` or binary response formats. Review the endpoint details before sending a request.

## Error handling

Reva APIs return standard HTTP status codes.

| Status code | Meaning |
|---|---|
| `200` | Request completed successfully. |
| `201` | Resource was created successfully. |
| `204` | Request completed successfully and no response body was returned. |
| `400` | Request payload, parameter, or input value is invalid. |
| `401` | Authentication is missing or invalid. |
| `403` | Caller is authenticated but not authorized to perform the action. |
| `404` | Requested resource was not found. |
| `409` | Request conflicts with an existing resource. |
| `500` | Internal server error. |

Error responses usually include a key, message, and optional data field.

```json
{
  "key": "INVALID.REQUEST",
  "message": "Request body is invalid",
  "data": "fieldName"
}
```

## Recommended integration flow  
For most integrations, follow this sequence:

1. Configure the application, environment, and policy store in Reva.
2. Define or import the authorization schema.
3. Ingest entities, attributes, and relationships using Data Fabric APIs.
4. Create and test policies in Reva.
5. Use Authorization APIs or AI Workload Authorization APIs to evaluate access.
