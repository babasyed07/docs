---
title: "Permissions for the Person Who Deploys"
---

These permissions are used once, to run the CloudFormation deploy. They are not the permissions the connector uses at runtime. A deployment role that can create IAM roles needs iam:CreateRole, iam:AttachRolePolicy, iam:PutRolePolicy, and iam:PassRole, together with cloudformation:CreateStack and cloudformation:UpdateStack.

| Deploy | The stack creates | The operator also runs |
| --- | --- | --- |
| EKS | An IAM role, two or three managed policies, and a Secrets Manager secret. No cluster, no node group, no repository. | eks:DescribeCluster to read the OIDC issuer, and the IAM rights to attach a policy to the existing node roles named in ImagePullRoleNames. |
| ECS | Two IAM roles, a secret, a log group, a security group, an ECS cluster, a task definition, and a service. | Nothing outside the stack, other than choosing an existing VPC and subnets. The deploy role needs ecs:*, ec2:CreateSecurityGroup, logs:CreateLogGroup, and the IAM actions above. |

Updating a secret value later needs secretsmanager:PutSecretValue on that secret. Forcing a new ECS deployment needs ecs:UpdateService. Helm install needs Kubernetes rights to create a namespace, a service account, and a deployment in that namespace. It does not need AWS rights beyond what the pod role already has.
