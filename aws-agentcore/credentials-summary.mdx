---
title: "Credentials Summary"
---
This page lists every credential involved in the External deployment, including who issues it, who holds it, and how to rotate or revoke it. Use this summary when your security team reviews the connector's access.

| Credential | Issued by | Held by | Notes |
| --- | --- | --- | --- |
| OAuth Token on Integration Details | Reva, when the integration is activated | The customer, in the Secrets Manager secret | This is the store API token. Paste it into the JSON field STORE_API_TOKEN. Regenerate Key replaces it. Update the secret and restart the workload. |
| EKS pod role | The customer stack | The reva-agentcore service account, through IRSA | No static key. Remove the role to revoke discovery. |
| ECS task role | The customer stack | The Fargate task | No static key. Scale the service to zero or delete the stack to stop it. |
| ECR pull | Customer node role or ECS task execution role, allowed by the publisher repository policy | The node or the execution role | Pull-only, one repository, in the Reva publisher account (`<REVA_ECR_ACCOUNT_ID>`) in us-east-1. |
| AWS access keys | Not used on the External path | Not stored | Access keys belong to the Internal deployment type. Do not put them in this secret. |
