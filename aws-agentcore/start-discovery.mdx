---
title: "Start Discovery"
---

An import reads the token, calls Reva for this integration’s configuration, scans the regions on the form, and pushes the entities to Reva. Start it from inside the pod or task, on port 8055.

```bash
curl --location 'http://localhost:8055/initImport' \
--header 'domain: {your domain}' \
--header 'username: {username}'
```

On EKS, from a workstation that has kubectl:

```bash
kubectl exec -it deployment/reva-agentcore -n rtg -- \
  wget -S -qO- --header="domain: customer" --header="username: admin" \
  http://localhost:8055/initImport
```

A successful call returns HTTP 202 Accepted with a runId, a connectionId, and status pending. HTTP 401 means the token is missing, still the placeholder, or no longer the token shown in the console. HTTP 409 means an import is already running for this connection. Wait for it to finish. The connector does not queue a second run.

When the import finishes, the connector pushes the entities to Reva. Confirm that in the connector logs and in the Reva ingestion logs. On ECS the connector log group is /ecs/reva-agentcore-discovery. On EKS use kubectl logs. A later Sync from the connector row in the console is separate from this first import. Use initImport for the external connector, because that path is what reads the token from Secrets Manager and pulls the configuration for this deployment.
