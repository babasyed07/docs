---
title: "Secrets Manager and the API Token"
---

The connector does not accept the token as a plain environment variable. At startup, and again when an import starts, it calls secretsmanager:GetSecretValue and reads one field from the JSON object.

| Variable | What it selects | When you can leave it unset |
| --- | --- | --- |
| STORE_TOKEN_SECRET_ARN | The secret ARN to read. STORE_TOKEN_SECRET_NAME is an alias and accepts a name or an ARN. | Do not leave it unset. The fallback secret name is store/secrets, which neither template creates. ECS sets this variable in the task definition. On EKS, set it in the Helm env block. |
| STORE_TOKEN_SECRET_KEY | The JSON field that holds the token. | Leave it unset when the field is STORE_API_TOKEN, which is the template default. Set it when you created a secret with a different field name. |

The secret string the connector can read looks like this:

```bash
{"STORE_API_TOKEN":"<OAuth Token copied from Integration Details>"}
```

Use either the secret the stack created or one you create:

1. Default. After the stack finishes, open the secret named by TokenSecretArn. Edit the JSON field STORE_API_TOKEN and paste the OAuth Token from the console as its value. The put-secret-value commands in sections [6.2](/aws-agentcore/deploy-on-an-existing-amazon-eks-cluster#put-the-reva-token-in-the-secret) and [7.2](/aws-agentcore/deploy-on-amazon-ecs-fargate#put-the-reva-token-in-the-secret) do that.

1. Your own secret. Create a secret in the same account. The value is a JSON object. Put the OAuth Token in the field you choose. Set STORE_TOKEN_SECRET_ARN to the secret ARN and STORE_TOKEN_SECRET_KEY to that field name. Grant the pod role or the task role GetSecretValue on that ARN. On EKS, the clean way to grant it is to pass the ARN as ExistingTokenSecretArn when you deploy customer-eks-permissions.json, and to set TokenSecretKey to the same field name.

The region used for the Secrets Manager call is the region embedded in the ARN. If the identifier is a name rather than an ARN, the connector uses AWS_REGION, then AWS_DEFAULT_REGION, then us-east-1.

After you regenerate the key in the console, paste the new token into the same JSON field and restart the pod or force a new ECS deployment. The running process does not watch the secret for changes.
