---
title: "Secrets Manager and the API Token"
---
The connector does not accept the token as a plain environment variable. At startup and whenever an import starts, it calls secretsmanager:GetSecretValue and reads a single field from the JSON object.

| Variable | What it selects | When you can leave it unset |
| --- | --- | --- |
| STORE_TOKEN_SECRET_ARN | The secret ARN to read. STORE_TOKEN_SECRET_NAME is an alias and accepts either a name or an ARN. | Do not leave it unset. The fallback secret name is store/secrets, which neither template creates. ECS sets this variable in the task definition. On EKS, set it in the Helm env block. |
| STORE_TOKEN_SECRET_KEY | The JSON field that holds the token. | Leave it unset when the field is STORE_API_TOKEN, which is the template default. Set it if you created a secret with a different field name. |

The secret string the connector can read looks like this:

```bash
{"STORE_API_TOKEN":"<OAuth Token copied from Integration Details>"}
```

You can use either the secret created by the stack or one you create yourself:

1. Default. After the stack finishes, open the secret identified by TokenSecretArn. Edit the JSON field STORE_API_TOKEN and paste the OAuth Token from the console as its value. The put-secret-value commands in Deploy on an Existing Amazon EKS Cluster and Deploy on Amazon ECS Fargate perform this update.

2. Your own secret. Create a secret in the same account. Its value must be a JSON object. Put the OAuth Token in the field of your choice. Set STORE_TOKEN_SECRET_ARN to the secret ARN and STORE_TOKEN_SECRET_KEY to that field name. Grant the pod role or task role GetSecretValue permission on that ARN. On EKS, the recommended way to grant this access is to pass the ARN as ExistingTokenSecretArn when deploying customer-eks-permissions.json and set TokenSecretKey to the same field name.

The region used for the Secrets Manager call is taken from the ARN. If the identifier is a name rather than an ARN, the connector uses AWS_REGION, then AWS_DEFAULT_REGION, and finally us-east-1.

After regenerating the key in the console, paste the new token into the same JSON field and restart the pod or force a new ECS deployment. The running process does not monitor the secret for changes.
