title: "Purpose and Scope"
description: "Setup, permissions, and network requirements for the external AWS AI Workload Discovery connector on Amazon EKS, Amazon ECS, and Amazon EC2."
---

This document is for the team that creates the AWS AI Workload Discovery integration in Reva and for the cloud, identity, and network teams that deploy the connector into the customer AWS account. It lists the console steps, the files in the deployment packages, the IAM permissions those packages create, and the network paths the connector uses.

The AWS AI AgentCore connector discovers Amazon Bedrock AgentCore and Amazon Bedrock agent resources in a customer account and sends them to Reva. In the external deployment described here, the connector runs in the customer account. Reva does not assume a role in that account and does not open a connection into the customer network. The connector calls Reva over outbound HTTPS, using a token the customer stores in AWS Secrets Manager.

## What it discovers

| Entity | Read from |
| --- | --- |
| Agent | AgentCore runtimes and classic Bedrock agents |
| MCP server | AgentCore gateways |
| Tool | Gateway targets |
| API | OpenAPI operations on gateway targets |
| Skill | Classic Bedrock agent action groups |
| Model | Models declared on the agents, and the Bedrock model catalog |
| Identity | IAM roles used by those agents, workload identities, and OAuth credential providers |

Discovery is read-only. The connector lists and reads AWS resources. It does not create, update, invoke, or delete them. The only secret value it reads is the Reva API token in the secret named by this deployment. It does not read customer application secrets, OAuth token values, or API keys stored for the agents it discovers.

All three deployment packages are provided in full. Each zip contains a README and a CloudFormation template. The EKS zip also contains the Helm chart and customer-values.yaml. The package the customer downloads for the option they choose is the complete set of files for that deployment.

| Package | File | Where it runs |
| --- | --- | --- |
| Deploy as EKS | agentcoreeks.zip | A pod in an existing Amazon EKS cluster. The zip contains the README, the permissions CloudFormation template, the Helm chart, and customer-values.yaml. IAM access is IRSA. There are no static AWS keys. |
| Deploy as ECS | agentcoreecs.zip | An Amazon ECS service on Fargate, created by CloudFormation in a VPC the customer already has. The zip contains the README and the full ECS CloudFormation template. |
| Deploy as EC2 | agentcoreec2.zip | An EC2 instance in the customer account. The zip contains the README and the full CloudFormation template for that deployment. After the stack is up, use sections [8](/aws-agentcore/secrets-manager-and-the-api-token) and [9](/aws-agentcore/start-discovery) for the token and the import. |

The console also offers an Internal deployment type. Internal runs the connector in Reva and takes AWS access keys, or an assume-role ARN, on the form. This document is the External path. Use one path for a given integration.
